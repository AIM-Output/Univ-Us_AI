## 읽는 법

- **병합본(A)이 더 나쁘다.** 1·8·9 에서 어댑터는 맞고 병합본은 틀렸다 — 틀린 방식도 "지난주를 조회", "도구 대신 되묻기", "거절 대신 삭제 제안" 처럼 학습 전 모델에 가까운 행동이다. 4-bit 가중치에 어댑터를 더하고 다시 양자화할 때 학습 효과가 깎인 것으로 본다. **그래서 서빙은 B(어댑터)로 둔다.** 병합본은 pod 재시작으로 베이스 캐시가 사라졌을 때의 비상용.
- **둘 다 틀린 것 셋**은 데이터·학습 쪽 문제다: ③ '다음 주 X요일'을 이번 주로 잡음(3회 모두 — 15:20 에 "다음 주 금요일 오전 10시 팀 회의" 도 11/6), ⑨ 학사일정 삭제 요청 거절 못 함(평가에서도 거절 65턴 중 29%), ⑪ `open_placement` 를 못 고름(평가에서도 13턴 전부 `list_events`).
- 평가(`eval_adapter.md`)에선 `create_event` 인자 일치 87% 였는데 여기 3번처럼 '다음 주' 가 들어간 문장은 평가셋 패밀리(`ce_F`)에 적어 수치에 덜 잡힌다.
- 12번: 학습 데이터에 "도구 결과 뒤 답변" 턴이 0개인데도 요약은 된다(베이스 능력). 어댑터 쪽이 학습 문체(짧게 · 링크)로 답한다.
