# 날짜 규칙 — 모델 답의 날짜를 코드로 덮어쓰기 (검증)

f9-r1 은 정답 날짜가 그 달의 말일·1일이면 3번에 1번꼴로 틀립니다([`../date_probe/`](../date_probe/)). 학습으로는 고쳐지지 않았습니다([`../f9-r1-date/`](../f9-r1-date/)).
날짜 계산은 답이 하나로 정해진 일이라 코드가 하게 했습니다. **모델은 f9-r1 그대로**이고, 모델이 낸 도구 호출의 날짜만 바꿉니다.

요구사항정의서 F9 5장도 "LLM 이 준 날짜 문자열은 백엔드가 다시 검증한다" 고 정해 두었습니다. 지금 앱 코드(`F9_Chat_agent`)는 달력에 없는 날짜를 거절하고 지난 날짜에 경고만 붙입니다. 고쳐 주지는 않습니다.

> `scripts/date_rule.py` 는 **검증용 원형**입니다(파이썬). 앱에는 아직 넣지 않았습니다.

## 규칙

사용자 문장에서 날짜 표현을 읽어(`src/prepare_f9_v2.py` 의 `parse_dates` · `parse_range`) 계산한 날짜로 바꿉니다. 시각 · 제목 · 분류 등 나머지는 모델 답 그대로입니다.

| 도구 | 언제 | 무엇을 |
|---|---|---|
| `create_event` | 문장에 날짜 표현이 **딱 1개**일 때 | `start` 를 그 날짜로, `end` 는 같은 간격만큼 옮김 |
| `list_events` | 날짜 표현이 있을 때 | `from` = `to` = 첫 날짜 |
| `list_events` | 날짜 표현은 없고 "이번 주 · 다음 주 · 다다음 주 · 주말 · 이번 달 · 다음 달" 이 있을 때 | `from` · `to` 를 그 범위로 |
| `update_event` | 날짜 표현이 2개("…을 …로 옮겨")일 때 | `patch.start` 를 둘째 날짜로, `patch.end` 는 같은 간격만큼 |
| 손대지 않음 | 반복 일정("매주" · "…마다") · 날짜가 2개 이상인 등록("…부터 …까지") · 날짜 표현이 없는 문장 · 그 밖의 도구 · 글로 답한 턴 | — |

처음에는 반복 일정과 "…부터 …까지" 등록도 바꿨는데, 학습 데이터 정답 38개를 틀리게 바꿔서 뺐습니다.

## 결과 — f9-r1 의 저장된 답에 적용해 다시 채점 (GPU 없이)

| 시험 | 규칙 전 | 규칙 후 | 규칙이 바꾼 턴 | 맞던 답을 틀리게 함 |
|---|---:|---:|---:|---:|
| eval 358턴 | 351 (98.0%) | **353 (98.6%)** | 2 | 0 |
| 날짜 진단 180문장 | 138 (76.7%) | **179 (99.4%)** | 41 | 0 |
| real_dev 189문장 | 178 (94.2%) | **181 (95.8%)** | 3 | 0 |
| real_test 191문장 | 180 (94.2%) | **182 (95.3%)** | 3 | 0 |

- eval 에 남는 5턴은 공강 배치 표기 문제입니다([`../f9-r1/`](../f9-r1/)). 날짜 진단에 남는 1문장은 날짜가 아니라 길이("한 시간 반" → 60분)가 틀린 것입니다.
- real_dev 는 159문장과 30문장을 따로 채점한 합입니다. real_test 는 개수만 봤습니다.
- 자세한 출력은 `apply_to_model_answers.txt` 에 있습니다. 실제 문장 쪽은 [`../f9-r1/`](../f9-r1/) 의 `real_dev_report_*.txt` · `real_test_report.txt` 입니다.

## 규칙이 정답을 망가뜨리지 않는가 — 정답에 적용

정답에 규칙을 적용했을 때 정답이 바뀌면 규칙이 틀린 것입니다(`apply_to_gold.txt`).

| 데이터 | 날짜가 들어가는 도구 턴 | 규칙이 날짜를 정한 턴 | 정답을 바꾼 턴 |
|---|---:|---:|---:|
| 학습 데이터 11,185행 | 5,693 | 4,942 | 0 |
| eval | 134 | 115 | 0 |
| 날짜 진단 | 180 | 180 | 0 |
| real_dev | 99 | 86 | 0 |
| real_test | 85 | 78 | 0 |

## 믿을 수 있는 정도

- **eval 과 날짜 진단 점수는 실제보다 좋게 나온 것일 수 있습니다.** 이 문장들은 규칙이 쓰는 것과 같은 생성기에서 나온 표현이라 규칙이 잘 읽는 것이 당연합니다.
- 실제 문장에서는 규칙이 날짜 턴의 87~92% 를 읽었습니다(dev 86/99 · test 78/85). 못 읽는 것은 반복 일정 · 기간 등록 · 날짜 표현이 없는 문장이고, 그때는 모델 답이 그대로 나갑니다.
- 실제 문장도 `make_real.py` 가 같은 함수로 날짜를 검사한 뒤에 올라온 것입니다. 팀이 쓰지 않은 표현은 재지 못했습니다.
- "X요일" 만 말한 문장은 이번 주의 그 요일로 읽습니다. 이미 지난 요일이면 과거 날짜가 됩니다.

## 길이 계산도 약한가 — 아닙니다

날짜처럼 길이(끝 시각 − 시작 시각)도 자주 틀리는지 f9-r1 의 답에서 세어 봤습니다(`dur_check.txt`).

| 시험 | 길이 표현이 있는 등록 문장 | 길이가 맞은 문장 |
|---|---:|---:|
| eval | 32 | 32 |
| 날짜 진단 | 54 | 53 |

한 번의 실수이고 반복되는 약점이 아니라서 규칙을 만들지 않았습니다. real_dev 에서는 "2시간짜리로" 1문장을 틀렸습니다.

## 다시 돌리는 법

```bash
PY=.venv/Scripts/python.exe
$PY scripts/date_rule.py apply outputs/f9-r1/eval_adapter.json data/f9/eval.jsonl        # 모델 답에 적용
$PY scripts/date_rule.py gold data/f9/train.jsonl                                        # 정답에 적용
$PY scripts/real_report.py outputs/f9-r1/eval_real_dev.json data/f9/real_dev.jsonl       # 실제 문장 — 묶음별 점수와 오답
$PY scripts/real_report.py outputs/f9-r1/eval_real_test.json data/f9/real_test.jsonl     # real_test 는 집계만 나옵니다
$PY -m unittest tests.test_date_rule -v                                                  # 규칙 자가 점검 17개
```

## 앱에 넣을 때

- 넣을 자리는 `F9_Chat_agent/chat/service.py` 의 `turn()` · `_dispatch()` 입니다. 사용자 문장과 지금 시각이 둘 다 있습니다.
- 수정·삭제는 모델을 두 번 부릅니다. 첫 호출(`list_events`)에도 규칙을 적용해야 대상 일정을 맞는 날에서 찾습니다.
- `tests/test_date_rule.py` 의 경우를 그대로 옮겨 시험하면 됩니다.
